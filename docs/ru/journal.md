# Golden Axe 3 (RUS) — тулкит для правки ROM

> Инженерный журнал проекта. Разделы до записи от 2026-09-10 описывают прежнюю раскладку
> (`tools/`, `work/`, `out/`, `scripts/`); актуальная структура и команды — в README и `docs/`.
> Витрина и быстрый старт — в [README.ru.md](../../README.ru.md) · [README.md](../../README.md).

Русификация от группы **NEWGAME, 2003** на базе `GOLDEN AXE 3` (Sega Mega Drive,
`GM 00004093-00`, (C)SEGA 1993.MAY). Образ 1 МБ, контрольная сумма `9BB5` сходится.

Эталон `Golden Axe 3 (RUS).bin` помечен только для чтения и не изменяется никогда.
Вся работа идёт на копии `work/ga3.bin`.

## Быстрый старт

```bash
# что за образ
python3 tools/romlib.py info work/ga3.bin

# выгрузить весь игровой текст
python3 tools/text_tool.py export work/ga3.bin -o text/strings.txt

# ... поправить text/strings.txt ...
python3 tools/text_tool.py verify work/ga3.bin text/strings.txt   # проверка без записи
python3 tools/text_tool.py import work/ga3.bin text/strings.txt   # вставка

# стартовое HP четырёх персонажей
python3 tools/balance.py show work/ga3.bin
python3 tools/balance.py set-hp work/ga3.bin 60 60 60 60

# патч для распространения без ROM
python3 tools/romlib.py ips "Golden Axe 3 (RUS).bin" work/ga3.bin -o out/patch.ips
```

## Карта ROM

| Область         | Содержимое                                                     |
|-----------------|----------------------------------------------------------------|
| `000000–0000FF` | таблица векторов (почти вся `FFFFFFFF`; по `0x40` втиснут код) |
| `000100–0001FF` | заголовок                                                      |
| `000200–000283` | таблица из 33 указателей — главный диспетчер                   |
| `000200–01C000` | код 68000                                                      |
| `00E492`        | **таблица HP персонажей** (4 байта: 51, 59, 67, 75)            |
| `0122FC`        | `NemDec` — распаковка Nemesis в порт VDP                       |
| `01230E`        | `NemDecToRAM` — распаковка Nemesis в память                    |
| `014E00–0151A0` | текст меню и опций                                             |
| `01C000–02C000` | Nemesis-сжатая графика (в т.ч. шрифт)                          |
| `01D85E`        | **шрифт**: 96 тайлов, Nemesis, без XOR, занимает 840 байт      |
| `080000–0D8000` | несжатый тайловый арт 4bpp                                     |
| `0E9B00–0EC300` | диалоги, титры, финал                                          |
| `0FC000–0FFA1F` | PCM-сэмплы                                                     |
| `0FFA20`        | точка входа (сдвинута русификатором с оригинальных `0x200`)    |

Это первая, приблизительная карта: границы и типы областей уточнены позже,
точные — в `rom_map.yml` и `docs/rom_map.md`.

**Свободного места 914 байт** в трёх дырках (`0116B6`, `05AEAA`, `05B30A`).
Текст длиннее оригинала на месте не поместится — потребуется `Rom.expand()` до 2 МБ.

## Как устроен текст

Текст лежит **открытыми байтами**, строки разделены `0xFF`. Шрифт грузится в VRAM так,
что **индекс тайла совпадает с байтом текста**, а кириллица посажена на позиции латиницы:

```text
ИГРОК  = D U H 0 R      (44 55 48 30 52)
ВДВОЕМ = B L B 0 N M
ОПЦИИ  = 0 G W D D
```

Полная таблица — `tools/table.py`. Она снята с игры, а не угадана: заглавные подтверждены
тайлмапом меню, строчные — тайлмапом диалога первого уровня. Экспорт/вставка проходят
round-trip байт в байт (202 строки, ноль расхождений).

Тонкости, которые легко упустить:

* Цифры `0` и `3` — те же глифы, что `О` и `З`; отдельных глифов для этих двух
  цифр в шрифте нет.
* Часть глифов казалась продублированной (`ж` — это и `0x26`, и `0x3B`; позже
  выяснилось: `0x26` — заглавная «Ж», `0x3B` — строчная). Байты, не переживающие
  round-trip, экспортируются как `{XX}` — текст остаётся читаемым, а правка точной.
* `0x71` — это `й` (тот же глиф, что `и` = `0x62`, плюс бревис сверху), а `0x50` — `ю`
  (ошибка: `0x50` — заглавная «Ю», строчная «ю» — `0x29`; см. «Вычитка текста»).
  На 8×8 их легко спутать; путаница даёт «магическию» вместо «магический».
* Некоторые экспортированные строки захватывают соседние байты данных
  (например `Ег   2ООЗ NЕWGАМЕ   Кч`) — правь только осмысленную часть.

## Как устроена графика

Сжатие — **Nemesis** (схема Sega). Реализация в `tools/nemesis.py` снята напрямую с
дизассемблера игры и проверена: распаковка блока `0x01D85E` совпала с дампом VRAM
**на все 3072 байта**.

```bash
python3 tools/nemesis.py work/ga3.bin 1D85E -o out/font.bin
python3 tools/romlib.py tiles out/font.bin 0 96 -o out/font.png --cols 16 --scale 4
```

Упаковщик тоже есть. `compress()` всегда проверяет себя распаковкой — молча
испортить графику нельзя. **Распаковщик самой игры читает наши блоки побайтово
идентично** (перепаковка шрифта без изменений даёт ту же VRAM, все 65536 байт).

По размеру на всех 14 Nemesis-блоках ROM упаковщик **не хуже оригинального**,
суммарно 13 780 байт против 14 045 (−265; размеры пересчитаны точным методом `ga3 nemesis size`, см. docs/nemesis.md):

| блок             | тайлов | XOR | в ROM | наш  | дельта |
|------------------|--------|-----|-------|------|--------|
| `013E76`         | 50     | нет | 413   | 375  | −38    |
| `01B780`         | 120    | да  | 1568  | 1563 | −5     |
| `01BDA0`         | 119    | да  | 1770  | 1759 | −11    |
| `01C48A`         | 120    | да  | 2112  | 2085 | −27    |
| `01CCCC`         | 81     | нет | 1034  | 1023 | −11    |
| `01D0D6`         | 81     | нет | 721   | 715  | −6     |
| `01D3A8`         | 31     | да  | 425   | 412  | −13    |
| `01D552`         | 21     | да  | 384   | 370  | −14    |
| `01D6D2`         | 40     | да  | 396   | 393  | −3     |
| `01D85E` (шрифт) | 96     | нет | 840   | 808  | −32    |
| `01DBAC`         | 20     | нет | 361   | 353  | −8     |
| `01DD16`         | 78     | да  | 1369  | 1342 | −27    |
| `01E29A`         | 18     | да  | 322   | 318  | −4     |
| `0295EE`         | 208    | нет | 2330  | 2264 | −66    |

Что понадобилось, чтобы догнать оригинал (первая версия проигрывала +400 байт):

* **Редкие серии выгоднее гнать inline.** Символ в таблице стоит 2 байта плюс
  `f * len` бит, inline — 13 бит за вхождение и ноль в таблице. Значит держать в
  таблице стоит только то, что окупает свои 16 бит: `f * (13 - len) ≥ 16`
  (при `< 16` символ уходит в inline).
  На XOR-блоках у оригинала 56 символов в таблице против сотни у наивного решения —
  почти 100 байт разницы. Диагностика показала это прямо: мой битовый поток был
  короче оригинального (11411 бит против 11499), а таблица — 223 байта против 128.
* **Длины кодов через package-merge**, а не эвристикой: обычный Хаффман даёт коды
  длиннее 8 бит, которые в формат не влезают.
* **Четыре зарезервированные записи таблицы** (`0xFC..0xFF` — признак inline)
  учитываются внутри package-merge четырьмя фантомными символами нулевого веса,
  а не удлинением кодов после. Одно это дало ещё 88 байт.

```bash
python3 tools/nemesis.py unpack work/ga3.bin 1D85E -o out/font.bin
python3 tools/nemesis.py pack out/font.bin -o out/font_packed.bin
python3 tools/nemesis.py size work/ga3.bin 1D85E     # сколько места на месте блока
```

Несжатый арт в `080000–0D8000` правится через `romlib.import_tiles`.

## Правка шрифта

Шрифт — один блок `0x01D85E` на все экраны: в меню используется тот же массив
с заменённым индексом фона (расходятся лишь 5 декоративных тайлов).
Фон в глифах — цвет 12, чернила — цвет 6, прозрачных пикселей нет
(из-за этого шрифт и не находился обычным поиском «двухцветных» тайлов).

```bash
python3 tools/font_tool.py info work/ga3.bin            # свободные слоты и запас места
python3 tools/font_tool.py export-art work/ga3.bin -o text/font.txt
# ... правка text/font.txt ...
python3 tools/font_tool.py import-art work/ga3.bin text/font.txt
```

Текстовый формат: заголовок `@ 4F`, затем 8 строк по 8 знаков, `#` — чернила,
`.` — фон. Комментарий помечается `;`, а не `#`: символ решётки в начале строки —
это пиксель.

В исходной русификации **не было букв Ъ и Ё и круглых скобок**. Дорисованы:

| знак | слот   | проверка                                                   |
|------|--------|------------------------------------------------------------|
| `Ё`  | `0x51` | в игре: `Вперед, храбрый воин!` -> `ВперЁд, храбрый воин!` |
| `Ъ`  | `0x4F` | только в данных шрифта (попадает в диалог второго NPC)     |
| `(`  | `0x2A` | в игре, скриншот `out/shots/parens.png`                    |
| `)`  | `0x2B` | в игре                                                     |

Все прописаны в `tools/table.py`. Демонстрации — `out/ga3_letters_demo.bin`
и `out/ga3_credits_demo.bin` (плюс IPS-патчи рядом).

### Куда вписать титр переводчика

Два места, оба без расширения ROM:

1. **Строка из 15 пробелов** по адресу `0x017AE3` — игра оставила её в концовке
   сразу после «волшебной легендой...». Готовая площадка, правится как обычная строка.
2. **Внутри самой фразы**, если уложиться в её поле. В `out/ga3_credits_demo.bin`
   сделано так: `0179F3` (24 байта) содержит `Наши воины (Гена и Женя)`, а следующая
   строка `уничтожили Принца Тьмы.` не тронута — вместе читается целой фразой.
   Исходное «И вот наши храбрые воины» не влезло бы с титром: 37 байт против 24.

Устройство блока концовки (`0x0179C0`–`0x017B00`): каждая строка идёт после
байта-отступа, `0xFF` — перевод строки, `0xFE` — конец экрана. Строки там плотно
подогнаны: например `0179F3` занимает ровно свои 24 байта, и сразу за ней `0xFE`,
так что дописать в неё нечего — следующий байт уже начало «уничтожили Принца Тьмы».

Свободных слотов в шрифте девять: `0x2A 0x2B 0x3C 0x3E 0x40 0x4F 0x51 0x7B 0x7F`.
Запас места после перепаковки — 29 байт, но он зависит от рисунка: чем больше
однородных серий пикселей, тем короче блок. С дорисованными Ъ и Ё запас 21 байт.
`font_tool` проверяет, что результат влезает, и отказывается писать, если нет.

## Эмулятор как измерительный прибор

В системе эмулятора не было, `apt` требует пароль sudo. Поэтому в `emu/headless/`
лежит собственный **headless-фронтенд к Genesis Plus GX**: без SDL, без libretro,
только libc и zlib.

```bash
make -C emu/headless
./emu/headless/headless_gpgx --rom work/ga3.bin --script scripts/dialog.txt
```

Команды сценария: `wait`, `press`, `hold`, `pad2`, `screenshot`, `dump`, `watch`,
`vwatch`, `bp`, `dmalog`, `poke8/16`, `state`, `reset`, `status`.
Полный список — `headless_gpgx --help`.

Именно этим найдено всё остальное: `bp 122FC` показал адрес источника Nemesis,
`vwatch` — куда грузится шрифт, `watch FFC8E6` — код, задающий HP.

### Три подводных камня GPGX

Стоили половины отладки, поэтому записаны:

1. **VRAM и SAT хранятся с перестановкой байт** (`*(uint16*)&vram[i] = data` на
   little-endian). Дампер отдаёт наружу честный big-endian.
2. **Work RAM тоже перевёрнута** (`READ_BYTE` = `(BASE)[(ADDR)^1]`): смещение `O`
   в дампе соответствует адресу 68000 `0xFF0000 | (O ^ 1)`. `ramsearch.py` это учитывает.
3. **DMA-копии не вызывают `cpu_hook`.** В `core/vdp_ctrl.c` добавлен крючок `dma_hook`
   (единственная правка ядра) — без него источник графики не найти.

Плюс к этому: игра адресует RAM как `FFFFxxxx`, а шина берёт 24 бита, поэтому
watchpoint'ы сравнивают адрес по маске `0xFFFFFF` и с учётом ширины доступа.

## Геймплей

`0x00E492` — таблица стартового и максимального HP четырёх персонажей.
Найдена так: `watch FFC8E6` показал, что значение `0x33` пишет код `0x00E48C`,
а дизассемблер вскрыл выборку по индексу персонажа:

```text
00E484  move.b  $144(a0), d0        ; индекс персонажа
00E488  move.b  $e492(pc, d0.w), d0 ; выбор из таблицы
00E48C  move.b  d0, $142(a0)        ; текущее HP
00E492  33 3b 43 4b                 ; <- таблица
```

Тот же массив служит потолком при лечении (код `0x00E49C`). Правка проверена
скриншотами: при `0x18` полоска здоровья заметно короче, при `0x7F` — во всю ширину.
Полоска в HUD рисуется пиксель на единицу HP и шире ~54 px не станет.

Жизни, магия и таймеры **не найдены** — метод для них тот же и упакован в
`tools/ramsearch.py`, но самой работы ещё нет.

## Что осталось за кадром

* Буква **Ъ** проверена только в данных шрифта: она попадает в диалог второго NPC
  («Не волнуйся, я разъярён!»), до которого нужно дойти по уровню. **Ё** проверена
  в игре скриншотом.
* Оптимальность упаковщика не доказана: нарезка серий уточняется динамикой по ценам
  символов, но сами цены зависят от нарезки, поэтому проходов делается два, а
  стратегий перебирается две (с inline и без). На всех блоках этого ROM результат
  не хуже оригинала, но гарантии на произвольных данных нет — поэтому `font_tool`
  сначала считает размер и отказывается писать, если блок не влезает.
* Свободных слотов в шрифте осталось пять: `0x3C 0x3E 0x40 0x7B 0x7F` (`0x2A`/`0x2B` заняли скобки).

## Проверка правок

1. **Структурная** — `romlib diff` показывает ровно ожидаемые байты, checksum пересчитана.
2. **Round-trip** — `text_tool verify` подтверждает, что текст читается обратно байт в байт.
3. **Динамическая** — прогон в headless-эмуляторе и чтение тайлмапа: правка
   «1 ИГРОК» → «1 ГЕРОЙ» подтверждена самой игрой (`тайлы: 31 20 55 4E 48 30 71`).
4. **Для графики** — перепаковка без изменений обязана дать байт-в-байт ту же VRAM.
   Это ловит ошибки упаковщика лучше любых глазных проверок.

## Запись от 2026-09-10 — реструктуризация в воспроизводимый конвейер

Проект переведён на структуру «эталон → `assets/` → `build/`» по образцу pret/pokecrystal,
sonicretro и sm64/oot. Что это меняет для читателя журнала:

* **Смещения теперь живут только в `rom_map.yml`.** Всё, что выше в этом журнале записано
  таблицами, — там сегментами с полем `evidence`. `ga3 map` печатает покрытие:
  опознано ~49 % образа, остальное честно помечено `unknown`.
* **Инструменты стали пакетом `src/ga3`** с одной командой `ga3` (extract / build / verify /
  map / assets / asm / …), докстринги и сообщения на английском. Ни одна команда больше
  не пишет в ROM на месте: эталон в `baserom/`, результат в `build/`.
* **Эмулятор**: ядро — submodule на форк `eugenez36/Genesis-Plus-GX`, ветка `ga3/dma-hook`
  (upstream `27426f0` + один коммит с хуком, CRLF сохранён). Сценарии разделены на
  `emu/scenes/` (регрессия, с `include`) и `emu/explore/` (одноразовые, для провенанса).
  Интерпретатор научился `include` и сам создаёт каталоги для скриншотов и дампов.

Два уточнения к сказанному выше:

1. **Размеры Nemesis-блоков.** Прежний `block_size` брал позицию ридера и занижал размер
   на 1 байт у 12 из 14 блоков; теперь считаются потреблённые биты. Точная сумма — 14 045
   байт (а не 14 033), наш упаковщик — 13 780. Слот шрифта — ровно 840 байт (`01D85E–01DBA6`),
   за ним 6 байт чужих данных до `01DBAC`. Раз наш упаковщик жмёт лучше оригинала,
   сборка переиспользует исходный `.nem` дословно, пока тайлы не изменены — иначе
   байт-идентичности не получить.
2. **Блок концовки.** Наблюдаемая структура: `отступ, строка, FE, отступ, строка, FF` —
   `FE` разделяет две строки экрана, `FF` завершает экран. Выше в разделе про титр
   написано наоборот; верно то, что здесь. Блок начинается с `0179F2`
   (`move.l #$179F2` в `0179E4`), а не с `0179C0`.

Перенос правок: эталон извлечён в `assets/` (коммит «Extract pristine assets»), затем
к копии эталона применены `letters.ips` + `credits.ips`, извлечено повторно — изменились
ровно четыре файла: `font.txt` (2A 2B 4F 51), `font.nem`, `ending.txt` (0179F3),
`dialogue.txt` (0EBBDC, 0EBC29). Вариант со скобками в титре (`strings_paren`) и демо
HP=80 (`demo_hp.ips`) сознательно не перенесены; сами IPS лежат в `docs/evidence/ips/`.

Дальше: жизни/магия/таймеры (`ga3 ramsearch`), палитры в ROM (по DMA-логу CRAM грузится
только из RAM — искать источник в коде), тайлмапы, таблица PCM-сэмплов.

## Версия в главном меню (0.3.6)

В правом нижнем углу главного меню теперь видно `V 0.3.6`: это номер из
`ga3.__version__`, его подставляет сборка.

* **Где рисуется меню.** Процедура `014F68` выводит четыре пункта по 7 символов в
  VRAM `C8A0 + n·0100` (плоскость A с `C000`, строка 128 байт, H40 — по регистрам VDP
  2, 16, 12) атрибутом `E000`, затем `moveq #0,d1; bra.w $15010` (курсор). Эти
  6 байт в `014F86` заменены на `jmp $0116B6.l`.
* **Процедура** (43 байта, новый тип сегмента `patch`, `src/ga3/patches.py`)
  собрана вручную: тот же цикл, что у пунктов меню, но для строки, выровненной вправо
  к столбцу 38 строки 26; в конце она повторяет `moveq #0,d1` и прыгает в `015010`.
  Место взято из начала свободной дырки `0116B6`; осталось 266 байт.
* **Буква V.** Латинской `V` в шрифте не было; она нарисована в свободный слот
  `0x40`. Свободных слотов осталось четыре: `0x3C 0x3E 0x7B 0x7F`.
* **Проверка.** Сцены `menu.txt` и новая `menu_options.txt`: строка есть в меню, на
  экране опций её нет (он очищается целиком), после возврата в меню она рисуется
  снова. Остальные 24 скриншота регрессии побайтно совпадают со сборкой без патча.
* **Инвариант «извлёк — собрал — получил эталон»** теперь верен везде, кроме слота
  патча, его хука и контрольной суммы: патч генерируется кодом, а не берётся из
  `assets/`. Тест так и проверяет.

## Вычитка текста (октябрь 2026)

Весь текст игры вычитан, ошибки исправлены; подробности, таблица правок и
предложения — в [proofreading.md](proofreading.md). Попутные находки:

* метки глифов `0x29`/`0x50` в таблице были перепутаны (строчная «ю» и заглавная
  «Ю»); текст в игре был верным, неверно читались файлы;
* «разъярён» в реплике 1 (демонстрация буквы Ъ, см. выше) откачено к тексту
  переводчиков: «я разберусь»;
* строки в коде (`ПАУЗА`, `ТЫ ПОГИБ`, `МАРШРУТ`, опции, `ОЧКИ`/`ЭТАП`) размечены
  ключом `strings` у сегментов кода;
* таблица реплик NPC — `0EBB42`, 16 смещений; заголовок реплики: ширина окна и
  «строк на экране − 1». Любую реплику можно показать в эмуляторе, направив на
  неё нулевой указатель в копии ROM;
* у реплики 1 окно было на 3 строки при 4 строках текста: «в округе.» не
  выводилось никогда.

## Счётчик убитых врагов

Рядом с HUD каждого игрока — синяя плашка с числом убитых им врагов (до 999;
сначала было до 99, но за игру врагов гораздо больше — счётчики стали словами,
плашка — на три цифры).
Подробности, адреса и проверки — `docs/patches.md`. Попутно:

* у игры есть встроенный выбор уровня: на экране выбора героя быстро A, A, A, A,
  START, C ×6, затем номер уровня стрелками (1, 2A, 2B … 7, 8). Код читается
  только с первого джойстика и только в игре на одного; код ставит флаг
  `FFF18B = 1`, курсор лежит в `FFF18A`, и при старте `00EE6A` переводит его
  в номер уровня `FFC776`. Чтобы в эмуляторе начать вдвоём с любого уровня,
  достаточно на экране выбора героев записать оба байта (`poke8`);
* убийство засчитывается игроку, который ударил врага последним, в том числе
  когда враг после удара упал с уступа (его объект освобождается с
  ненулевым HP); врага, которого никто не трогал, не получает никто;
* магия стирает графику HUD в видеопамяти, а после неё игра возвращает спрайты
  HUD на 6–12 кадров раньше, чем их графику; то же на старте уровня. Поэтому
  счётчик рисуется, только когда рамки всех трёх блоков HUD игрока уже в VRAM,
  иначе цифры висели бы рядом с пустым HUD;
* шрифт диалогов лежит в видеопамяти только на уровнях 1 и 7, поэтому счётчик
  держит свои тайлы цифр в `D700` (таблица окна, на уровнях не используется);
* код патча пишется на ассемблере (`assets/patches/*.s`) и собирается
  встроенным `ga3.m68k`; каждая поддержанная инструкция проверяется
  дизассемблером;
* мусорная запись текста поверх кода (`014FFB` в `menu.txt`) молча затирала бы
  перехват — такие записи убраны, извлечение текста ограничено областями
  `prose`, а сборка проверяет, что правки патчей уцелели.

## Поиск ошибок (октябрь 2026)

Готовых сведений о падениях версии для Mega Drive в открытых источниках нет,
поэтому игру гонял бот: все 13 уровней через встроенный выбор уровня, один
игрок и двое (для двоих код выбора уровня не работает, его флаг и курсор
выставляются через `poke8`, см. «Счётчик убитых врагов»). Векторы исключений
указывают на `FFFFFFFF`, так что любая ошибка процессора дала бы зависание;
его искал по промежуткам между вызовами ожидания кадра (`00F006`).

* Зависаний нет ни в одном прогоне. Длинные промежутки (35–125 кадров) — это
  анимации магии с собственным ожиданием VBlank.
* Пауза, все пункты опций (сложность, четыре раскладки кнопок, тест музыки и
  звуков), отказ от продолжения после гибели, карта с «ТЫ ПОГИБ» и возврат к
  заставке работают; текст на этих экранах влезает в свои места.
* Свои ошибки нашлись в счётчике убитых: цифры появлялись раньше графики HUD
  после магии, а обход всего списка спрайтов каждый кадр замедлял бой вдвоём
  (на 6A вместо 47 потерянных кадров из 1239 — 297). Обе исправлены до слияния.
  В дуэли врагов нет, и счётчики всегда показывали 0 — там они больше не
  рисуются (режим `FFF176` ≥ 2).
* **Ошибка перевода:** на карте под «ОЧКИ» стоит не этап, а оценка игрока
  (AAA … F), подпись «ЭТАП» заменена на «РАНГ». Шкалу проверил подстановкой
  значений 0–7 в `FFF180` прямо перед выводом карты.
* **Финал** проверен в игре: через выбор уровня сразу на уровень 8,
  бессмертный бот с зельями побеждает босса, дальше без нажатий идут сцена
  спасения, прокрутка текста концовки (с правками вычитки), «THE END», карта
  с «ОЧКИ / РАНГ» и возврат к заставке. Зависаний нет. При прокрутке строки на
  мгновение проходят под картинкой топора справа внизу — так устроен экран.
  Игра, начатая через выбор уровня, после одного этапа возвращается к
  заставке, поэтому титры с авторами и карта между этапами в полном
  прохождении так не проверяются.
* Подстановка `HP = 1` врагам каждые несколько кадров ломает подсчёт:
  убитого врага она воскрешает, и счётчик крутится до предела. Для бота лучше
  бессмертный игрок с зельями и магией.
* Удобный приём для честного сравнения скорости двух сборок: `state save`
  посреди боя и одинаковый ввод с этого состояния на обоих ROM; иначе прогоны
  расходятся по случайным числам.

## Таблицы геймплея: жизни и кредиты

Жизни и кредиты лежат не в таблице, а прямо в коде — это операнды команд:

* **жизни** игрока — байт `+0x13C` его объекта (`FFC8E0` у P1); дампы RAM, пока
  P1 трижды гибнет на уровне 1, дают 2, 1, 0 вместе с цифрой в HUD. При старте
  игры их ставит `00E420 move.b #2,$13c(a0)`, при продолжении —
  `00E6E8` (та же команда рядом с `subq.b #1,$c77c.w`); `00697A` отнимает одну
  при гибели, `010416` добавляет одну (доп. жизнь, условие ещё не разобрано);
* **кредиты** (продолжения) — `FFC77C`, их ставит `0003B6 move.b #4,$c77c.w`,
  каждое продолжение отнимает одну. От сложности обе константы не зависят
  (сложность выбирает данные врагов, `00E3D2`).

Вырезать однобайтовый сегмент из кода нельзя — он разрежет команду и её
листинг. Поэтому появился блок `constants:` в `rom_map.yml`: для каждой
константы — команды, которые её несут, их байты в эталонном ROM и смещение
операнда. Сборка сверяет байты и пишет значение, `ga3 balance set lives 5`
правит `assets/data/gameplay.yml`. Проверено в эмуляторе на сборке с 5 жизнями
и 9 кредитами: в HUD «5», на экране продолжения «КРЕДИТЫ 9», после продолжения
снова 5 жизней и 8 кредитов.

## Характеристики героев (октябрь 2026)

Полное исследование параметров четырёх героев — в `docs/heroes.md`
(таблицы, адреса, проверенные пределы). Главное:

* номер героя на экране выбора (`FFF315`: 0 Хронос, 1 Каин, 2 Сара, 3 Прауд)
  переводится таблицей `0x160FA` в «класс» `+0x131` (Прауд 0, Каин 2, Хронос 3,
  Сара 4); класс 1 — крылатый человек-зверь, доступный только в дуэли;
* различаются только удары (таблица приёмов `0x0EED40`: сила = 2 × урон),
  темп ударов (скрипты анимации), скорости ходьбы, рывка и прыжка (`0x337E6`,
  `0x337FA`, формат 8.8) и вид магии;
* одинаковы у всех: здоровье (таблица `0x00E492` — по **уровню** здоровья
  `+0x144`, а не по герою, как считалось раньше), урон магии
  (`0x00F91A`: 6 / 16 / 32, вместе 56), зелья (1…6), защита, восстановление;
* HP выше `0x7F` смертельно для героя; сила удара `0xFF` с переносом давала
  в счётчике убитых HP 203 вместо нокаута — исправлено (PR #25).

## ROM 2 МБ

Свободного места в исходном 1 МБ почти не осталось (28 байт), а для панели
характеристик на экране выбора героя нужны код, строки и тайлы. Образ сборки
расширен до 2 МБ: в `rom_map.yml` ключ `rom.build_size: 0x200000`, новый
мегабайт — свободный сегмент `free_100000` (`FF`). Эталонный дамп остаётся
1 МБ и сверяется по SHA-1 как прежде; конец ROM в заголовке (`1FFFFF`) и
контрольная сумма пересчитываются при сохранении (мегабайт `FF` сумму не
меняет). Чтобы IPS не вырос на мегабайт, запись IPS научилась RLE-записям:
патч стал больше всего на 142 байта. Игра работает как прежде: все сцены,
`ga3 lag` — те же 233 потерянных кадра из 3438.

## Характеристики на экране выбора героя

Выбран вариант В (шкалы). Панель рисуется на этапе сборки
(`src/ga3/hero_panel.py`): глифы шрифта, рамка и шкалы в цветах палитры 0
экрана выбора, 68 уникальных тайлов, раскладки для каждого героя — на всю
ширину для одного игрока и по половине для двоих. Перехват — на процедуре
курсора `016278` (она выполняется раз в кадр для каждого игрока); тайлы
кладутся в свободную видеопамять `3C40` (на этом экране туда никто не пишет),
раскладка — в плоскость A поверх заголовка. Панель перерисовывается при смене
героя и сама восстанавливается, если игра перерисовала экран. В дуэли панели
нет. Числа сверяет тест с таблицами ROM.

## Косая черта в шрифте

Удар и суперудар в панели писались через дефис («6-18»), который читается как
диапазон. В пустой слот `3E` нарисована «/» (наклон в два пикселя, как у
курсива игры), в таблицу кодировки добавлен символ. Блок шрифта после
перепаковки — 837 байт из 840, свободными остаются `7B` и `7F`. Панель теперь
занимает 64 уникальных тайла вместо 68. Проверено в эмуляторе: «8/24», «6/18»,
«5/15» на экране выбора; диалоги и все сцены регрессии без изменений.

## Зелья магии

Третья константа геймплея — зелья (`+0x140` объекта игрока). Наблюдение за
`FFC8E4` от включения: `00E47C move.b #1,$140(a0)` срабатывает при старте
игры, после каждой смерти и после продолжения, но только если зелий нет
(перед ним `tst.b $140(a0)`); с 4–5 зельями те же смерти и продолжение их не
трогают. Подбор прибавляет одно и упирается в 6 (`000A1A cmpi.b #6`), HUD
рисует шесть как три полные банки, а при 9 выводит мусор из чужих тайлов.
Поэтому у констант появился жёсткий предел `max` (у зелий 6): больше не
пропустят ни `ga3 balance set`, ни сборка. Проверено на сборке с 6 зельями:
на старте три полные банки, A вызывает магию второго уровня и тратит все шесть.
